# BUG-004: Zip/postal code field accepts invalid characters with no validation

**Severity:** Medium
**Environment:** Chrome, saucedemo.com, logged in as standard_user

## Steps to Reproduce
1. Log in to saucedemo.com as standard_user / secret_sauce
2. Add an item to cart, proceed to checkout
3. Enter valid first name and last name
4. Enter an invalid/nonsensical value in the postal code field (e.g., random symbols/letters)
5. Click Continue

## Expected Result
Checkout should reject clearly invalid postal code input, or at minimum enforce
a basic format check

## Actual Result
Checkout proceeds successfully regardless of postal code format — no validation
is enforced on this field

## Impact
Invalid address data could flow downstream into order fulfillment/shipping in
a real production system. Low severity for this demo app, but a real
data-quality issue in a live e-commerce context
